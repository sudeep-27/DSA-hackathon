The running-time graph is a separate benchmark: it generates several larger inputs and measures both algorithms at each size. It is separate because a full benchmark takes longer than a single comparison.

The code below is the Python solution to submit. Plain HTML in a browser cannot execute CPython directly, so the interactive controls and canvas use an equivalent JavaScript implementation to keep this file working offline; the displayed Python code implements the same two algorithms.

Input: one integer N. The program generates N random integer-coordinate points.
import random
from math import sqrt
from time import perf_counter


def squared_distance(a, b):
    """Return the squared Euclidean distance between two (x, y) points."""
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    return dx * dx + dy * dy


def brute_force(points):
    """Check every pair. Returns (minimum_squared_distance, pair), or None."""
    if len(points) < 2:
        return None

    best_sq = float("inf")
    best_pair = None
    for i in range(len(points) - 1):
        for j in range(i + 1, len(points)):
            d_sq = squared_distance(points[i], points[j])
            if d_sq < best_sq:
                best_sq = d_sq
                best_pair = (points[i], points[j])
    return best_sq, best_pair


def divide_and_conquer(points):
    """Closest pair in O(N log N), using x-sorted and y-sorted point lists."""
    if len(points) < 2:
        return None

    # Add an ID so duplicate coordinates can still be split consistently.
    tagged = [(float(x), float(y), i) for i, (x, y) in enumerate(points)]
    by_x = sorted(tagged, key=lambda p: (p[0], p[1], p[2]))
    by_y = sorted(tagged, key=lambda p: (p[1], p[0], p[2]))

    def small_case(items):
        best_sq = float("inf")
        best_pair = None
        for i in range(len(items) - 1):
            for j in range(i + 1, len(items)):
                dx = items[i][0] - items[j][0]
                dy = items[i][1] - items[j][1]
                d_sq = dx * dx + dy * dy
                if d_sq < best_sq:
                    best_sq = d_sq
                    best_pair = (items[i], items[j])
        return best_sq, best_pair

    def solve(px, py):
        n = len(px)
        if n <= 3:
            return small_case(px)

        middle = n // 2
        left_x, right_x = px[:middle], px[middle:]
        left_ids = {p[2] for p in left_x}
        left_y = [p for p in py if p[2] in left_ids]
        right_y = [p for p in py if p[2] not in left_ids]
        split_x = (left_x[-1][0] + right_x[0][0]) / 2.0

        left_best = solve(left_x, left_y)
        right_best = solve(right_x, right_y)
        best_sq, best_pair = left_best if left_best[0] <= right_best[0] else right_best
        d = sqrt(best_sq)

        # Only points within d of the dividing line can beat the current answer.
        strip = [p for p in py if abs(p[0] - split_x) <= d]
        for i in range(len(strip)):
            # In y-order, geometry means only the next seven points need checking.
            for j in range(i + 1, min(i + 8, len(strip))):
                dy = strip[j][1] - strip[i][1]
                if dy * dy >= best_sq:
                    break
                dx = strip[j][0] - strip[i][0]
                d_sq = dx * dx + dy * dy
                if d_sq < best_sq:
                    best_sq = d_sq
                    best_pair = (strip[i], strip[j])
        return best_sq, best_pair

    best_sq, pair = solve(by_x, by_y)
    if pair is None:
        return None
    # Drop the internal IDs; return the original coordinate format.
    original_pair = ((pair[0][0], pair[0][1]), (pair[1][0], pair[1][1]))
    return best_sq, original_pair


def print_result(label, result):
    if result is None:
        print(f"{label}: N/A | pair: N/A (N < 2)")
        return
    distance_sq, (p, q) = result
    distance = sqrt(distance_sq)
    print(
        f"{label}: {distance:.6f} | "
        f"({p[0]:g}, {p[1]:g}) and ({q[0]:g}, {q[1]:g})"
    )


if __name__ == "__main__":
    # Input is N. The program generates N random integer-coordinate points.
    n = max(0, int(input().strip() or "0"))
    points = [
        (random.randint(-100, 100), random.randint(-100, 100))
        for _ in range(n)
    ]

    start = perf_counter()
    brute_result = brute_force(points)
    brute_ms = (perf_counter() - start) * 1000

    start = perf_counter()
    divide_result = divide_and_conquer(points)
    divide_ms = (perf_counter() - start) * 1000

    print_result("Brute-Force", brute_result)
    print_result("Divide-and-Conquer", divide_result)
    print(
        f"Execution time: Brute-Force {brute_ms:.4f} ms | "
        f"Divide-and-Conquer {divide_ms:.4f} ms"
    )

Why the algorithms work

Algorithm notes

Brute-Force

Time: O(N²) · Extra space: O(1)

It checks all N(N−1)/2 pairs and keeps the shortest one. It is simple and reliable for small inputs, but the number of pairs grows quickly as N increases.

Divide-and-Conquer

Time: O(N log N) · Extra space: O(N)

It sorts the points, splits them into left and right halves, recursively finds the best distance in each half, and checks only the narrow strip around the dividing line. This avoids comparing every possible pair.

Why check a strip of width 2d?

Let d be the smaller closest-pair distance found in the left and right halves. A cross-half pair can only be closer than d if both points are within d of the dividing line, so the relevant vertical strip has total width 2d. After sorting strip points by y-coordinate, geometry limits the number of nearby points that need checking (at most the next seven in the standard 2D algorithm).

Why keep both methods? Brute-Force is the easy reference implementation. Divide-and-Conquer is faster for large N. Comparing their minimum distances is a practical correctness check. When multiple pairs tie, the exact pair printed can differ even though the minimum distance is correct.

Corner cases and correctness notes

N < 2: no pair exists, so the distance and pair are reported as N/A. Duplicate coordinates: minimum distance is 0. Ties: either equally close pair is correct. Same x or y / collinear points: handled without slope division. Negative and decimal coordinates are also supported by the interactive input.

The algorithms compare squared distances internally, avoiding square roots during pair comparisons. A square root is used only when formatting the final result.
